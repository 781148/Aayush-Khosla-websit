Platform Tag Game Learning Logs

Learning Log #1 – Variables & Data Tracking

One of the main concepts I used in my game were variables for storing different types of data. It was needed because the game needs to track movement, physics scores and timers. 

float p1X, p1Y;
float p1Vy = 0;
boolean p1OnGround = false;

int p1Score = 0;
int p2Score = 0;

boolean isP1It = true;
int gameState = 0;

I used the float variables for the players positions and velocities because gravity often requires decimals values. Integer variables were used for timers, and game state since they are whole umbers. Finally boolean variables were used for true/false conditions lik weather or not a player is on the ground. The variables are used throughout the game such as p1X to store the players position on the screen. I chose this approach since each variable has a purpose and using the correct data types improves efficiency. Once challenge I faced was keeping track of the variables while debugging the players movement. I fixed this by grouping variables that were related.

Learning Log #2 – Selection Structure

I used election structures throughout my game to make decisions based on player action or conditions. 

if (p1Jump && p1OnGround) {
    p1Vy = jumpForce;
    p1OnGround = false;
}

if (seconds >= 0) {
    timeRemaining = seconds;
} else {
    gameState = 2;
}

This structure is used in player movement and checks two condition before allowing the player to jump. If both conditions are true then p1 is able to jump. I implemented these selection structures because games constantly need to make decisions based on changing conditions. Without these checks, players could jump infinitely or the game would not know when to end a round. One challenge I encountered was preventing players from jumping repeatedly while already in the air. Initially, players could sometimes trigger multiple jumps. I fixed this by checking the p1OnGround and p2OnGround variables before allowing a jump.

Learning Log #3 – Repetition Structure

One repetition structure I implemented in my game is a for loop that checks platform collisions for the players. 

for (int i = 0; i < platX.length; i++) {
   float platLeftEdge  = platX[i] - platW[i]/2;
   float platRightEdge = platX[i] + platW[i]/2;
   float platTopEdge   = platY[i] - platformHeight/2;

   if (p1X > platLeftEdge && p1X < platRightEdge) {
      float playerFeetY = p1Y + playerSize/2;

      if (p1Vy >= 0 &&
          playerFeetY >= platTopEdge &&
          playerFeetY <= platTopEdge + landingThresholdY) {

         p1Y = platTopEdge - playerSize/2;
         p1Vy = 0;
         p1OnGround = true;
      }
   }
}

I used this loop to check each platform in the game. Instead of writing collison code for each platform a loop is able to go through all platforms in the stored array. It starts at index 0 and loops through and calculates if the player is on top of the platforms.One challenge I encountered was players occasionally falling through platforms. To fix this, I added a landing threshold variable that gives the collision system a small detection range. This made platform landings more reliable.

Learning Log #4 – Arrays & Data Structures

I used arrays to store information about all of the platforms in my game. 

float[] platX = {150, 350, 550, 750, 900};
float[] platY = {450, 460, 440, 470, 430};
float[] platW = {140, 120, 150, 110, 130};

for (int i = 0; i < platX.length; i++) {
    rect(platX[i], platY[i], platW[i], platformHeight);
}

These arrays store the X positions, Y positions, and widths of every platform. Each index represents a single platform. I access the information using a loop. This loop draws every platform in the game using the values stored in the arrays. I chose arrays because they allow me to store multiple platforms efficiently. Without arrays, I would need separate variables for every platform, making the code much longer and harder to manage. One challenge was making sure that all platform arrays had the same number of elements. If one array had fewer values than another, the game could produce errors. I solved this by ensuring each platform's X position, Y position, and width were stored at the same index across all arrays.

Learning Log #5 – Custom Functions & Error Checking

I created several custom functions to organize my code and make the program easier to manage. 

void timer() {
  int seconds = 30 - ((frameCount - startFrame) / 60);
}

void checkTagContacts() {
  if (dist(p1X, p1Y, p2X, p2Y) < playerSize) {
    isP1It = !isP1It;
  }
}

The timer() function controls the countdown timer and determines when the round ends. The checkTagContacts() function checks whether the two players are touching and swaps who is "It." I chose to place these tasks into separate functions because it makes the code easier to read and maintain. I also implemented restrictions such as preventing players from moving off screen and preventing jumping while already in the air. One challenge I encountered was organizing the growing amount of code. I solved this by splitting logic into separate functions.
