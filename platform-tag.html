Learning Log #1 – Variables & Data Tracking

One of the main concepts I used in my game is variables for storing and tracking game data. Different variables were needed because the game tracks player movement, physics, scores, timers, game states, and user input. 

float p1X, p1Y;
float p1Vy = 0;
boolean p1OnGround = false;

int p1Score = 0;
int p2Score = 0;

boolean isP1It = true;
int gameState = 0;

I used float variables for player positions and velocity because movement and gravity often require decimal values for smooth motion. Integer variables were used for scores, timers, and game states because they represent whole numbers. Boolean variables were used for true/false conditions such as whether a player is on the ground or whether Player 1 is currently "It."

The variables are used throughout the game. For example, p1X and p1Y store the player's position on the screen, p1Vy stores vertical speed for jumping and gravity, and p1Score keeps track of points earned during the match.

I chose this approach because each variable has a specific purpose and data type that matches the information being stored. Using the correct data type improves organization and efficiency.

One challenge I encountered was keeping track of many different variables while debugging player movement. To solve this, I grouped related variables together and added comments to make the code easier to read and maintain.

Learning Log #2 – Selection Structure

I used selection structures throughout my game to make decisions based on player actions and game conditions. 

if (p1Jump && p1OnGround) {
    p1Vy = jumpForce;
    p1OnGround = false;
}

This selection structure is used in the player movement system. The game checks two conditions before allowing a jump: the jump key must be pressed and the player must be standing on the ground. If both conditions are true, the player jumps.

Another example is the game timer: 

if (seconds >= 0) {
    timeRemaining = seconds;
} else {
    gameState = 2;
}

This decision determines whether the round continues or ends when time expires.

I implemented these selection structures because games constantly need to make decisions based on changing conditions. Without these checks, players could jump infinitely or the game would not know when to end a round.

One challenge I encountered was preventing players from jumping repeatedly while already in the air. Initially, players could sometimes trigger multiple jumps. I fixed this by checking the p1OnGround and p2OnGround variables before allowing a jump.

Learning Log #3 – Repetition Structure

One repetition structure I implemented in my game is a for loop that checks platform collisions for the players. 

for (int i = 0; i < platX.length; i++) {
   float platLeftEdge  = platX[i] - platW[i]/2;
   float platRightEdge = platX[i] + platW[i]/2;
   float platTopEdge   = platY[i] - platformHeight/2;

   if (p1X > platLeftEdge && p1X < platRightEdge) {
      float playerFeetY = p1Y + playerSize/2;

      if (p1Vy >= 0 &&
          playerFeetY >= platTopEdge &&
          playerFeetY <= platTopEdge + landingThresholdY) {

         p1Y = platTopEdge - playerSize/2;
         p1Vy = 0;
         p1OnGround = true;
      }
   }
}

I used this loop to check every platform in the game. Instead of writing separate collision code for each platform, the loop automatically checks all platforms stored in the arrays.

The loop starts at index 0 and continues until it reaches the last platform. During each iteration, the code calculates the platform boundaries and determines whether the player has landed on that platform.

I chose this method because it reduces duplicated code and makes adding new platforms much easier. I only need to add new values to the arrays rather than writing additional collision code.

One challenge I encountered was players occasionally falling through platforms. To fix this, I added a landing threshold variable that gives the collision system a small detection range. This made platform landings more reliable.

Learning Log #4 – Arrays & Data Structures

I used arrays to store information about all of the platforms in my game. 

float[] platX = {150, 350, 550, 750, 900};
float[] platY = {450, 460, 440, 470, 430};
float[] platW = {140, 120, 150, 110, 130};

These arrays store the X positions, Y positions, and widths of every platform. Each index represents a single platform.

I access the information using a loop: 

for (int i = 0; i < platX.length; i++) {
    rect(platX[i], platY[i], platW[i], platformHeight);
}

This loop draws every platform in the game using the values stored in the arrays.

I chose arrays because they allow me to store multiple platforms efficiently. Without arrays, I would need separate variables for every platform, making the code much longer and harder to manage.

One challenge was making sure that all platform arrays had the same number of elements. If one array had fewer values than another, the game could produce errors. I solved this by ensuring each platform's X position, Y position, and width were stored at the same index across all arrays.

Learning Log #5 – Custom Functions & Error Checking

I created several custom functions to organize my code and make the program easier to manage. 

void timer() {
  int seconds = 30 - ((frameCount - startFrame) / 60);
}

void checkTagContacts() {
  if (dist(p1X, p1Y, p2X, p2Y) < playerSize) {
    isP1It = !isP1It;
  }
}

The timer() function controls the countdown timer and determines when the round ends. The checkTagContacts() function checks whether the two players are touching and swaps who is "It."

I chose to place these tasks into separate functions because it makes the code easier to read and maintain.

I also implemented restrictions such as preventing players from moving off screen and preventing jumping while already in the air.

One challenge I encountered was organizing the growing amount of code. I solved this by splitting logic into separate functions.
